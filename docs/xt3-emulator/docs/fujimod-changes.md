## Catalog facts to propose (X‑T3 5.11)

- RAM 1 GiB (catalog: 512 MiB).
- Power controller: register 16 = 4 (power‑on reason), register 4 = 900 (battery, threshold 752), 13 = 27 = 0.
- Card detect: GPIO 10.4, active low. SD slots `0xfffc4000`/`0xfffc8000`, UHS‑II banks `0xfffc6200 + n·0x4000`.
- 66 register blocks with evidence (to convert into `soc.json` entries through the generators).
- **`catalog/firmware/xt3/5.11/firmware.json`, `unit-7` size: `8224768` → `9494528`** (applied locally).
  The listed size is unit‑6's; with it the section's own SHA‑256 cannot match. The recovery recipe
  (`catalog/recovery/recipes.generated.json`, region `overlays`, DAT offset 10224244, raw) already has
  9,494,528 bytes with the same digest. Checked by unpacking the official 5.11 update: all eight sections
  then match the catalog digests. Still present upstream at `1462468`; introduced by `4c9dd26e`
  (2026‑10‑21, “Add XP4 and XP5 firmware run records”), the only commit that ever touched this file. No open
  PR or issue mentions it as of 2026‑11‑07 (no duplicate).
- Static track progress (`catalog/progress/xt3/5.11/progress.generated.json`, applied locally):
  `flash-reader` = pass (the XP4 packet‑flash locator contract reproduced against the image; upstream
  #150 shares the fact), `research` = pass (update registered, unpacked, corpus exported). Facts count unchanged at 15/22: it comes from the analysis facts document, not from these stages.
